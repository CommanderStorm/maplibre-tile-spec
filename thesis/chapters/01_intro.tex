\chapter{Introduction}\label{ch_introduction}

Interactive web maps have become a ubiquitous interface for geographic information, powering applications from navigation and logistics to urban planning and journalism.
Modern map renderers such as MapLibre GL~JS and Mapbox GL~JS deliver rich, client-side rendered vector maps by streaming tiled geometry data to the browser, where a client side style specification drives a WebGL- or WebGPU-based rendering pipeline.
This architecture enables smooth panning, zooming, and rotation, but it also places competing demands on the network (tile fetching), the CPU (decoding, style expression evaluation), and the GPU (draw calls)- all within a single frame budget.

As map deployments scale - from personal projects to platforms serving millions of daily users - the cost of suboptimal performance compounds.
Larger tiles increase transfer time and bandwidth cost; redundant style layers waste rendering cycles; unnecessary properties inflate decoding overhead.
On mobile devices, these inefficiencies translate directly into battery drain and thermal throttling.
On unstable network connections, such as on trains or aeroplanes, these translate to degraded user experiences.

Despite this, the map rendering and geospatial community has largely treated style authoring and data preparation as independent concerns:
\begin{itemize}
    \item styles are hand-tuned for visual appearance,
    \item tiles are encoded with general-purpose content and compression.
\end{itemize}

The interaction between the two is left unexploited.

\section{Research Goals}\label{sec_research_goals}

This thesis investigates automatic, style- and data-driven co-optimisation for MapLibre-based map rendering pipelines.
Three research questions guide the work:

\begin{enumerate}[label=\textbf{R\arabic*}]
    \item To what extent \textbf{can automatic data and style co-optimisation reduce map tile size and improve rendering performance}?
    \item \textbf{Which techniques} - such as expression simplification, dead layer elimination, layer merging, tile shaving, and columnar re-encoding - \textbf{are most effective}, \textbf{and how do they interact}?
    \item \textbf{How expensive are these optimizations} in terms of preprocessing time, and what are the \textbf{tradeoffs between transfer size, decoding latency, and rendering throughput}
\end{enumerate}

To answer these questions, the thesis designs and implements a standalone optimiser that consumes a MapLibre style JSON document and, optionally, tile-level statistics, and produces a semantically equivalent style whose rendering performance is measurably improved - together with optimised tile data.

All transformations are visually lossless:
The optimised output must produce pixel-identical rendering for every tile at every zoom level.

\section{Contributions}\label{sec_contributions}

The main contributions of this thesis are:

\begin{enumerate}
    \item A \textbf{two-phase style optimization pipeline} comprising expression-level rewrites (constant folding, algebraic simplification, stats-driven folding, selectivity reordering) and structural passes (dead layer elimination, metadata refinement, layer merging), modeled on peephole optimisers and query planners from the compiler and database literature.

    \item \textbf{Style-driven tile shaving} that computes a pruning advisory from the optimised style, enabling removal of unused properties, geometry types, property values, and feature IDs from tile data - creating a cascade where style optimisation makes data optimization more effective.

    \item An \textbf{automatic encoding strategy selection} for the MapLibre Tiles (MLT) columnar format that reformulates tile encoding as a multi-strategy competition over sort orderings, integer encodings, and string compression strategies.

    \item An \textbf{empirical evaluation} across 15 styles, 18 scenarios, and 17 cumulative ablation steps, demonstrating measurable improvements in tile volume, load time, and rendering stability.
\end{enumerate}

\section{Outline}\label{sec_outline}

The remainder of this thesis is structured as follows.

\cref{ch_related_work} surveys existing work across four areas - tile data pruning (vtshaver, vt-optimizer, Tippecanoe), tile encoding and format innovation (MVT, MLT, columnar compression), style-level tooling (migration utilities, CSS minification analogues), and rendering performance benchmarking - and identifies the gap that motivates the co-optimisation approach: no existing system composes style rewrites with data-level pruning into a single pipeline.

\cref{ch_theoretical_background} establishes the foundations the optimiser builds on.
It introduces the map rendering architecture and its resource pipeline (tiles, styles, fonts, sprites), surveys compiler optimisation techniques (peephole rewriting, constant folding, fixpoint iteration) and query optimisation concepts (predicate pushdown, selectivity reordering) whose analogues are applied to style expressions and filters, describes the columnar encoding and compression schemes used at the tile level, and formalises the multi-objective optimisation problem that the methods chapter addresses.

\cref{ch_methods} presents the design and implementation of the optimiser itself.
It describes the two-phase pipeline - expression-level passes on raw JSON followed by structural passes on typed Rust representations generated from the MapLibre style specification - and details each individual pass: constant folding, algebraic simplification, stats-driven folding, dead layer elimination, metadata refinement, and layer merging.
The chapter then extends the pipeline to the data level with style-driven tile shaving and automatic encoding strategy selection for the MLT columnar format, and concludes with the benchmarking methodology, including scenario design and the cumulative ablation protocol.

\cref{ch_experiments} evaluates the optimiser through three experiments that mirror the pipeline's structure: expression-level optimisations (eight passes evaluated in cumulative ablation order), structural optimisations (six passes with inter-pass dependency analysis), and data-level optimisations (tile shaving and MLT encoding strategy competition).
A cross-style generalisation study across 15 styles tests robustness beyond the deep benchmarking corpus, and a combined analysis quantifies the full pipeline's end-to-end effect on tile volume, load time, and rendering stability.

\cref{ch_conclusion} revisits the three research questions in light of the experimental evidence, summarises the cascade effect between style-level and data-level optimisations as the central architectural finding, discusses limitations, and identifies directions for future work including symbol layer merging, runtime re-encoding, and formal multi-objective search.
